## 2. เรื่อง git — ทำไมถึงค้าง และแก้ยังไง

อาการ: `git status` แสดง `src/` ทั้งโฟลเดอร์เป็น untracked ทั้งที่ไฟล์อยู่ครบ

สาเหตุ: repo อยู่ในโฟลเดอร์ Synology Drive commit ถูกสร้างและ push จากเครื่องอื่น (macOS) แล้ว sync ลงมา — object ใน `.git` มาครบ (จึงมี `origin/main`) แต่ **ตัวชี้ HEAD ไม่ได้ตามมาด้วย** ไฟล์บนดิสก์เลยใหม่กว่าที่ HEAD รู้จัก

วิธีแก้ที่ใช้ (ไม่ใช้ `reset --hard` เพราะเสี่ยงเกินจำเป็น):

| ขั้น | คำสั่ง | ทำอะไร |
| :--- | :--- | :--- |
| 1 | `git reset origin/main` | เลื่อน branch pointer + index **ไม่แตะไฟล์เลย** |
| 2 | `git show HEAD:<path> > <path>` | กู้ 3 ไฟล์ที่หายจริง — `.dockerignore`, `.env.example`, `.prettierrc` |

ตรวจก่อนทำด้วยการสร้าง index ชั่วคราวแล้ว diff กับ `origin/main` — ยืนยันว่าเนื้อไฟล์บนดิสก์**ตรงกับ `origin/main` อยู่แล้ว** จึงไม่มีอะไรสูญหาย

> ### ⚠️ ข้อควรระวังที่สำคัญที่สุดของ repo นี้
> **`.git` อยู่ในโฟลเดอร์ที่ Synology Drive sync** — ระหว่างทำงานรอบนี้มีไฟล์หายจากดิสก์ระหว่างทาง 2 ครั้ง (`6610110189.zip` และ `old_architecture.md`)
> สองเครื่อง commit ลง `.git` เดียวกันผ่าน file sync ทำให้ repo พังได้จริง
> **ควร sync ผ่าน `git push` / `git pull` แล้วย้าย repo ออกนอก sync root**

## 3. `docs/Meta/primer-template.md` — ของหลักของรอบนี้

### 3.1 มันคืออะไร

`architecture-primer.md` ไม่ได้ดีเพราะมันพูดเรื่อง Redis แต่ดีเพราะมันเรียง **ทำไม → ใคร → เดินยังไง → พังยังไง → ทดสอบตัวเอง** ซึ่งไม่ผูกกับเนื้อหา
เทมเพลตนี้ถอดชั้นโครงนั้นออกมาเป็น prompt ที่เติมตัวแปร 11 ตัวแล้วสั่ง LLM เขียน primer ของวิชาอะไรก็ได้

### 3.2 scrutinize ด้วย 3 agent — ฉบับแรกไม่ผ่าน

| มุม | คำตัดสิน | blocker หลัก |
| :--- | :--- | :--- |
| prompt mechanics | rework | `SOURCE_OF_TRUTH` รับแค่ **ชื่อไฟล์** ที่โมเดลเปิดไม่ได้ · payload **ไม่เคยสั่งงาน** · `SUBJECT`/`AUDIENCE` ประกาศแล้วไม่ถูกอ้างถึง |
| cross-discipline | rework | โครงบังคับทำให้ทุก § ที่ไม่เข้ากับวิชากลายเป็น**จุดแต่งเรื่อง** ทดสอบกับปรัชญา/ประวัติศาสตร์แล้วพังเกินครึ่ง |
| fidelity กับต้นฉบับ | fix-then-ship | อุปกรณ์ที่หนาแน่นที่สุดของต้นฉบับ (อ้าง § ของสเปก **56 ครั้งใน 1,042 บรรทัด**) ถอดไม่ติดเลย |

**รากของปัญหาข้อเดียว**: ไฟล์เตือนเองว่า "ถ้าไม่มีแหล่งอ้างอิง LLM จะเติมของที่ฟังดูดีแต่ผิดลงในทุกช่อง" แล้วส่งชื่อไฟล์ให้โมเดลที่เปิดไม่ได้ พร้อมโครง 13 หัวข้อที่ห้ามเว้นว่าง — failure mode ที่คำเตือนบรรยายไว้จึงกลายเป็นผลลัพธ์รับประกันของทุกการรันที่ทำตามคำสั่งถูกต้อง

### 3.3 ฉบับที่ 2 แก้อะไรบ้าง

**เพิ่มชั้นปูพื้นฐาน** (ที่ฉบับแรกไม่มีเลย — มีแต่ชั้นโครง):

1. **บันไดความรู้** — แตกศัพท์ให้หมดรวมคำที่ซ่อนในคำ เรียงตามลำดับพึ่งพา ทำเป็นตารางที่มีคอลัมน์ "สอนที่" กับ "ใช้ครั้งแรกที่"
2. **หนึ่งศัพท์ต้องครบ 5 ช่อง** — ปัญหาเดิม / นิยาม / อุปมาที่ยึดกับ `FLOOR` / ในงานจริงคือตัวไหน / **กับดักของศัพท์นี้**
3. **ศัพท์ถูกสอน 3 ที่** — กล่อง 📖 ตรงที่เจอครั้งแรก, ช่อง "ศัพท์" ท้ายตัวละครใน §2, แล้วค่อยรวบที่ §10 (**glossary คือที่รวบ ไม่ใช่ที่สอน**)
4. **กฎห้ามใช้ศัพท์ก่อนสอน** — กฎเดียวในไฟล์ที่ตรวจได้เชิงกล
5. **ตัวแปรใหม่ `FLOOR`** — เพดานล่างที่ไม่ต้องสอน คู่กับ `FROM_ZERO`

**ปิด blocker:**

- `<SOURCE_MATERIAL>` เป็นบล็อกให้แปะเนื้อหาจริง ว่างแล้วต้องหยุด
- บรรทัดแรกเป็นประโยคสั่งงานที่ผูก `SUBJECT`/`AUDIENCE` เข้าไป
- `<GATE>` ให้ตอบ 3 คำถามก่อนเขียน แล้ว**ปิด §6/§7 ทิ้ง**ถ้าวิชานั้นไม่มีของแบบนั้น
- กฎอ้างอิงต่อข้อบังคับ `[SOURCE §x.y]` ถ้าอ้างไม่ได้ให้เขียนว่า "เป็นการตีความ"
- rubric กลายเป็น **prompt รอบสองที่ต้องรันจริง** ไม่ใช่ตารางให้ไล่ด้วยตา

**แก้ข้อเท็จจริงที่ผิดในฉบับแรก 10 ข้อ** ที่สำคัญ:

| ผิดยังไง | แก้เป็น |
| :--- | :--- |
| เขียน "12 ส่วน" แต่มี 13 (§0–§12) | นับใหม่ให้ตรง เส้นทางย้ายเป็น §3.1/§3.2 เลขจึงไม่เลื่อน |
| อ้างว่า `architecture-primer.md` เป็น *ผลลัพธ์* ของเทมเพลต | เป็น *ต้นทาง* ที่ถูกถอดโครง — เทมเพลตยังไม่เคยผลิตอะไร |
| §1.4 ถอดเหลือคำคุณศัพท์ "วัดได้จริง" | ของจริงคือ SQL ที่ **รันได้** + ค่าที่ต้องได้เป๊ะ + ความหมายของการเบี่ยงเบนทั้งสองทาง |
| §7 บังคับ "ต้องมีสถานะทางตัน" | ต้นฉบับเขียนตรงข้าม — **ห้ามมีทางที่ค้าง** ทุกสถานะต้องมีทางออก |
| กฎ mermaid "เส้นง่ายสุดห้ามใช้ไดอะแกรม" | ผิด — Read Path มี sequenceDiagram 36 บรรทัด สิ่งที่ต่างจริงคือ**ความยาว** (84 vs 199) |
| §2 ให้ "มันคืออะไร" มาก่อน | ละเมิดกฎข้อ 1 ของตัวเอง — ต้นฉบับนำด้วย **ปัญหาเดิม** เสมอ |
| ตารางแปลงข้ามศาสตร์มี 2 ช่องผิด | ตัดทิ้งใส่ 🚫 — เศรษฐศาสตร์/คณิตศาสตร์ ไม่มีวงจรชีวิตแบบ §7 |

### 3.4 ที่ตั้งและชื่อ

## 5. สิ่งที่ยังค้าง

- **เทมเพลตยังไม่เคยรันจริงสักครั้ง** — ควรลองกับวิชาหนึ่งแบบ end-to-end ก่อนเอาไปใช้จริง มุม cross-discipline เตือนว่ากับวิชาที่ไม่มี "ระบบ" จะพังเกินครึ่งถ้าไม่ผ่าน `<GATE>`
- **`docs/Codebase/Separate/01-codebase-primer.md` มีข้อมูลผิดที่ยังไม่ได้แก้** (สำรวจไว้แล้วรอบนี้ แต่ยังไม่ลงมือ):
  - §6 ยังเขียนว่า read path **โยน 503** ตอน redis-data ล่ม — โค้ดจริงแก้เป็น degrade ไปแล้ว (`products.service.ts:124-137`)
  - §11 เขียนว่า "ไม่มีทาง reset" ทั้งที่ `database/reset.ts` มีอยู่ — และ §13 ในไฟล์เดียวกันเขียนถูก **ขัดกันเอง**
  - §3 บอก "48 ไฟล์ใน `src/`" จริงมี **49** และตกไป **17 ไฟล์**
  - `file:line` เพี้ยน **14 จุด** กระจุกอยู่ใน 4 ไฟล์ที่แก้รอบ 2026-08-26
  - `app.module.ts` ประกอบ **10 module** ไม่ใช่ 9 (§4 วาดเอง 10)
- **`scripts/build-all-in-one.mjs` มีบั๊ก** — `.split('\n### 📎 อ่านต่อ')[0]` ไม่เคยทำงาน เพราะหัวข้อจริงมีเลข `14.` คั่น ทำให้ไฟล์ที่ generate มี "อ่านต่อ" ซ้ำ 2 ที่ (บรรทัด 511 กับ 751)
- สถานะเดิมที่ยังไม่ขยับ: **ยังไม่เคยรัน container · ยังไม่เคยยิง k6 · ไม่มี e2e test · ยังไม่ได้ทำรายงาน PDF**
